# 전경 구조와 국소 윤곽을 분리하는 실험 점수

`stroke_model/source_quality_v5.py`. 기존 v4 점수·추출기·체크포인트를 변경하지 않고
저장된 원본/기준/기준 획 배열로 새 진단을 병렬 계산한다. single/multiglyph 코랩의
5번 셀에서 이전 점수와 새 진단을 함께 표시한다. 생성·추출을 다시 실행할 필요는 없다.
새 모듈을 받으려면 같은 세션에서 최신 노트북의 1번 셀을 실행한 뒤 5번 셀을 실행한다.

## 구성

1. **전경 증거:** `x*sigmoid((x-.12)/.03)`을 x=1에서 1이 되도록 정규화한다.
   매우 옅은 배경 성분을 줄이되 입력을 이진화하거나 윤곽을 매끈하게 바꾸지 않는다.
   원본과 기준 모두 같은 함수를 거친다. 원본은 별도로 보존한다. 실제로 옅은 획도
   약해질 수 있으므로 검정 글자·밝은 배경인 현재 실험 범위의 가정이다.
2. **전경 구조 점수:** 원래 source의 등록 변환을 고정한 채 기존 누락/단절/정션/추가
   잉크 측정과 집계 공식을 재사용한다. 추가 잉크의 가중치를 낮추는 수정이 아니다.
3. **윤곽 진단:** 전경 입력과 기준을 같은 좌표에서 .35/.5/.65로 각각 검사한다.
   signed distance field와 sigma=1.5px Gaussian smoothing의 차이를 경계에서 측정한다.
   기준의 1px 이웃에 이미 있는 반응과 .08 허용량을 빼고 초과분만 평균한다.
   원래 기준에 있는 모서리/세리프는 기준 반응으로 허용한다. 주황/파랑은 볼록/오목
   초과 반응 후보이며 의미적으로 확정된 돌출/패임 정답은 아니다. 곡선·래스터링·다른
   정상 글꼴에서도 반응할 수 있어 스타일 불변성을 주장하지 않는다.
4. **실험 집계:** `contour_cap=100*exp(-contour_excess/.05)`.
   `experimental_score=min(foreground_structural_score,contour_cap)`.
   .05 등의 숫자는 사람이 정한 pilot 시작 설정이며 사람 품질에 보정하지 않았다.
   표에서 전경 구조·윤곽 초과량·윤곽 상한·실험 총점을 따로 확인해야 한다.

기본 거리 단위는 현재 128x128 글자 입력의 픽셀이다. 자동으로 전 글꼴·다른 해상도에
맞춰 보정되지 않는다. 단순한 점수 상승을 정확도 개선으로 해석하지 않는다.

## 범위와 저장

새 점수도 Topo의 마스크 품질을 숫자로 평가하지 않는다. 실제 입력과 기준을 직접 본다.
윤곽 반응은 CPU threshold/distance transform 기반으로 **미분 불가능**하므로 현재
그대로 역확산 guidance 손실에 넣을 수 없다. 역확산 적용은 별도 미분 가능한 대체 항과
수정 방향의 검증이 필요하다. 이미지 전경 게이트와 기존 source 측정만 gradient가 유지된다.

`quality_v5_시간` 폴더에 PNG, 원본·전경·윤곽 지도 NPZ, 비교 CSV와 설정 JSON 저장.
기존 진단 ZIP에 별도 하위 폴더로 넣으며 v4 측정/결과는 덮어쓰지 않는다.

검사: `python -m unittest discover -s tests -p test_source_quality_v5.py -v`.
연결이 유지된 작은 돌출/패임, 같은 기준의 세리프, 옅은 배경, 진한 추가 획과 전경
게이트의 gradient를 검사한다. 이는 전체 정상 글꼴의 오탐률 검증과는 다르다.
