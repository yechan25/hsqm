# 선택한 획에 기준 획을 매핑하는 Colab

실행: notebooks/repair_audit/attribute_straightness.ipynb. GPU에서 셀 1→6.

1. 설치 및 포함된 런타임 준비.
2. 기존 best.pt/자료 경로 확인, 목록·로컬 썸네일 준비 후 글자/입력 폰트 선택.
3. 기존 추출기와 SD1.5 로딩, 2×2 공동 생성 1장 및 정상 원본에서 획 추출.
4. 생성물/정상 원본과 칸을 고르고, 획 그림 아래 버튼 클릭. 매핑한 목표 미리보기 확인.
5. 일반 재역확산/선택 획 매핑 가이드를 동일 초기 상태로 비교. nominal120×.25=실제30스텝.
6. 현재 결과 ZIP 다운로드. 생성/추출 및 보정 결과는 Drive에도 백업.

문자명은 파일명/메타데이터에서 읽는다. NanumGothic 한 기준 폰트를 모든 입력 폰트에 공유하며,
해당 문자 기준이 없으면 후보 목록에서 제외한다. 입력 폰트의 정답 획을 보정에 쓰지 않는다.
기존 모델 구조/가중치/공통 DDIM 샘플러를 사용한다.

stroke_model/attribute_guidance.py는 선택한 기준 획의 중심선을 관측 획의 두 끝점에 맞춰 이동·회전·등방 확대/축소한다.
관측 마스크의 주 성분에서 중앙 구간 반두께의 중앙값을 재고, 해당 값 하나로 출력 해상도에서 렌더링한다.
폐곡선, 경로 지지가 부족한 획, 매우 짧은 획은 보류한다. 추출 오류로 끝점이나 대응이 틀릴 수 있어 목표를 확인한다.
다른 획의 코어/교차부를 목표 편집에서 보호하고, 영역 밖 목표 픽셀은 입력과 같다.
대표 두께와 원형 끝단을 사용하므로 입력 폰트의 삐침이나 테이퍼는 단순해질 수 있다. 교차부 보호 경계에는 단차가 남을 수 있다.
흰색/단순 배경에 한정한 실험이다. 입력과 VAE/확산 결과의 비선택 영역 동일성은 보장하지 않는다.
30스텝 설정 자체가 품질 향상의 근거는 아니다. 실제 GPU 품질과 속도는 실행 전 미검증이다.
