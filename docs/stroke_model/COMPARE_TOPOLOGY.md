# 튜닝 전후와 실제 보조 주석 진단

[비교 코랩](https://colab.research.google.com/github/yechan25/hsqm/blob/main/notebooks/compare_topology.ipynb)

재학습하거나 가중치 파일을 덮어쓰지 않는다. 동일한 전처리 텐서를 두 모델에 전달한다.
튜닝 후 best.pt는 최신 v2_topology_runs에서 찾고, 튜닝 전은 해당 실행의
initial_checkpoint_source.txt에 기록된 실제 초기화 경로를 읽는다. 기록이 없으면 직접 지정해야 한다.
그냥 시간상 직전 폴더를 튜닝 전이라고 추측하지 않는다. 모델 경로와 메타데이터를 출력한다.

기본은 CSV의 modified 이미지 전체다. SAMPLE_ROWS로 특정 행을 선택하거나,
INPUT_IMAGE에 이전 캔버스 input.png를 지정하고 REFERENCE_ROW를 선택할 수 있다.
각 모델에 다시 그린 다른 그림을 사용하지 않는다. 기본 관심 획은 4/5번이며 None이면 전체다.

전후 soft/exclusive, 변경 픽셀, 채널 간 이동 수, 획별 픽셀/연결 성분 수,
튜닝 후 1위-2위 확률 차이를 표시한다. 낮은 최대 확률(<0.5)과 낮은 margin(<0.15)은
진단용 구분값이며 예측을 수정하거나 픽셀을 삭제하는 임계값이 아니다.
4→5 픽셀이 늘거나 줄었다는 것만으로 개선을 판정할 수 없다. 실제 정답/원본과 대조해야 한다.
comparison.json에 입력 텐서 SHA256과 설정을 남기고 원시 확률/flow/hints를 NPZ로 저장한다.

마지막 셀은 run_config.json의 학습 manifest가 현재 런타임에 있으면 그 안의
ownership_path를 읽어 **실제로 저장된 주석**을 표시한다. 없으면 그 사실을 표시한다.
학습 런타임의 raw NPZ와 보조 주석 캐시가 필요하다. TRAIN_ROWS는 train manifest 행 번호이며
테스트 CSV 행 번호가 아니다. 테스트/캔버스에 기준 획을 적용해 가짜 학습 정답을 만들지 않는다.
새로 그린 입력은 실제 학습 사례가 아니므로 그 입력의 학습 정답이 존재한다고 가정하지 않는다.
주석이 틀리면 지도 생성 오류의 증거가 될 수 있지만, 다른 입력의 주석을 특정 테스트 오류의
확정 원인으로 삼을 수 없다.

진단 수치/그림 생성과 모델 파일 불변성을 합성 fixture로 확인한다. 실제 전후 체크포인트는
사용자 Drive에 있으므로 아직 비교하지 않았다. 실제 개선/악화 판정은 실행 결과 확인 후 수행한다.
