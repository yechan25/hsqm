# 기준 네 글자로 다양한 생성물을 만든 뒤 획 변형 비교

[4셀 Colab](https://colab.research.google.com/github/yechan25/hsqm/blob/main/notebooks/stroke_reference_fit_sweep.ipynb)을 L4에서 실행한다. 기존 한 장의 오류 이미지에 대한 `stroke_reference_fit.ipynb`는 유지하며, 이 확장판은 초기 img2img 생성 셀과 전 케이스 처리 루프를 추가한다.

1. Drive 연결, 기존 ZIP/생성 폴더에서 네 기준 글자와 획 조건 복원, 당시 best.pt SHA256 검사. 이 단계의 이전 오류 이미지는 기본 생성 입력으로 쓰지 않는다.
2. 네 기준 글자를 2×2로 합친 정상 이미지에서 독립적인 img2img를 실행한다. 기본 강도 .45/.65/.85 × seed 100/101, nominal steps 100으로 생성물 6장과 정상 입력 대조군 1장을 저장한다. 프롬프트만으로 생성하는 실험이 아니고 기준 이미지 초기화 실험이다. 이전 생성 결과를 다음 입력으로 연결하지 않는다. 모델 revision, scheduler, prompt, 실제 입력, strength와 seed가 generation_report.json에 기록된다. 강도/seed가 특정 오류를 반드시 만들지는 않는다.
3. 정상 입력 포함 7개 모두에서 네 칸의 softmax/마스크/hints를 추출한다. 모델은 한 번 로딩하고 케이스마다 별도 폴더와 NPZ를 저장한다.
4. 7개 모두에 원본 획 변형과 학습 추출기 없는 대조군을 적용한다. 전체 입력/후보/대조군 비교 그림과 케이스별 경고·fallback 수 요약을 저장한다. 최종 후보를 이용한 추가 보정 역확산은 이 단계에서 수행하지 않는다.

SHOW_DETAILS_FOR=(3,)은 기본적으로 .65/seed100의 상세 그림만 펼치는 화면 설정이다. 처리 대상을 거르는 설정이 아니며 모든 케이스의 파일과 전체 비교를 남긴다. 다른 상세 케이스를 보려면 2번 셀을 다시 돌려 생성할 필요 없이 SHOW_DETAILS_FOR 값을 새 셀에서 바꾸고 3/4번을 다시 실행할 수 있다. INPUT_MODE='saved'이면 기존 오류 이미지 한 장을 처리하는 모드도 가능하다.

강도/seed를 바꿔 2번 셀을 다시 실행하면 새 sweep 폴더를 만들어 이전 결과와 섞이거나 덮어쓰이지 않는다. 사용한 기준 획 조건과 출처도 전체 ZIP에 포함한다.

안전 필터 결과, 오류 없는 결과, 심한 붕괴, 빈 추출까지 임의로 제외하지 않는다. 빈/불확실한 추출에서 기준을 남기는 fallback은 경고 및 획 개수로 표시한다. 합성 후보가 정상이라는 의미가 아니고, 이 비교만으로 누락 복원 성능이나 획 추출 모델의 고유 효과가 입증되지는 않는다.

생성 파이프라인은 2번 셀 종료 후 정리하고 그다음 획 추출기를 로딩한다. 기본 설정은 한 장 버전보다 생성/추출/도표 저장 시간이 늘어난다. 결과는 /content에서 계산한 뒤 Drive의 HSQM/stroke_reference_fit_sweep_results에 ZIP으로 복사한다.

테스트는 mock 생성기로 모든 강도/seed 조합의 독립 입력과 필터 결과 보존을 확인한다. CPU mock 추출기로 빈 이미지 포함 여러 케이스의 추출/변형 셀을 실제 실행해, 개별 출력 및 전체 요약이 덮어쓰이지 않는지 검사한다. 이 테스트는 실제 SD 생성 다양성이나 실제 체크포인트 품질 검증과 구분한다.
