# 저장된 오류 이미지의 3셀 재역확산 시험

`notebooks/saved_repair_demo.ipynb`를 코랩에 업로드한다. 로컬 런타임 헬퍼를 노트북에 포함하므로 Git 커밋/업로드가 필요하지 않다. L4로 실행하며 Qwen은 로딩하지 않는다. SD1.5는 새로운 첫 생성이 아니라 기존 이미지의 재역확산에만 사용한다.

Drive 연결 창에서 막힐 때는 `notebooks/saved_repair_demo_no_drive.ipynb`를 사용한다. 이 버전은 drive.mount를 호출하지 않고 기존 ZIP과 당시 획 추출기 best.pt를 각각 업로드받는다. SHA256 대응 검사는 유지한다. 결과는 /content의 세션 임시 저장소에 기록하므로 종료 전에 결과 ZIP을 다운로드해야 한다. 코랩 사이트나 런타임 자체에 접속할 수 없는 문제는 이 우회로 해결되지 않는다.

1. 준비 및 `guidance_debug (4).zip` 업로드. 최초 baseline PNG를 바이트 그대로 복원하고 당시 기준 획 배열과 checkpoint SHA256을 읽는다. checkpoint는 기존 Drive 파일을 사용하며 모델이 다르면 중단한다. 학습 데이터 ZIP/CSV를 다시 풀 필요는 없다.
2. 기존 획 모델의 추출 결과와 기준 획 범위 밖 추가 잉크 지도를 표시한다. 기본은 좌상단 가만 선택하며 모델 좌표에서 3픽셀 여유를 둔다. 정상 기준 획 합집합 내부는 삭제 대상에서 제외한다. 목표 배경은 현재 오류 이미지 주변에서 추정한다. 기준 획 자료를 가이드에 사용하는 통제된 실험이며 참조 없는 검출 실험이 아니다. 사람이 마스크를 확인한 후 3번 셀을 실행한다.
3. 동일하게 VAE 인코딩하고 잡음을 추가한 잠재값으로 baseline/guided를 비교한다. 기본 100 steps × .35 = 35 actual steps. 가이드는 매 단계 VAE 디코딩 손실을 clean latent에 미분해 수정하고 손실이 내려갈 때 채택한다. 최종 RGB를 직접 칠하지 않는다. 전체/가 확대 비교, 고정 영역 진단값, clean 예측 GIF, 추적 로그와 ZIP을 저장한다.

## 무엇을 주장할 수 있는가

우선 목표는 기준 획 가이드가 있을 때 저장된 오류 이미지의 재역확산 보정이 가능한지 확인하는 것이다. 새 prompt-only 한글 생성 성능, 참조 없는 오류 검출 성능, 획 추출 모델 고유의 기여를 이 데모 성공만으로 주장하지 않는다.

특히 partition 모델은 전체 마스크 합이 입력 잉크와 같다. 모든 기준 획의 합집합 밖만 지우는 실험에서는 획 추출 결과를 합친 지도가 단순 기하 비교 지도와 같아질 수 있다. 노트북은 두 지도 IoU를 기록하고 .98 이상이면 모델 고유의 이득으로 해석하지 말라고 표시한다. .98 미만이고 기하 가이드가 존재하면 같은 잡음의 별도 기하 가이드 대조군도 실행한다. 따라서 향후 모델 기여는 그 대조군보다 유의미한 개선이 있는 사례로 확인해야 한다.

기존 ZIP 생성 방식은 출처 report 그대로 보존한다. 과거 report에 init_mode가 없으면 미기록으로 표시하며 prompt-only 생성이라고 해석하지 않는다. baseline/guided의 출발 이미지 모두 오류 생성물이며 깨끗한 기준 이미지를 VAE 출발점으로 사용하지 않는다.

## 확인 범위

실제 사용자가 제공한 (4).zip의 baseline 및 네 기준 획 복원, 기준 조건 catalog 생성, 저장된 실제 baseline soft mask로 가이드와 삭제 목적함수 구성이 가능한지 로컬 CPU에서 확인했다. 합성 예제로 입력 PNG 무변경, 정상 획 보호, 지정 슬롯 밖 가이드 차단을 검사했다. GPU의 실제 삭제량과 정상 획 보존 품질은 코랩 실행 전에는 확인되지 않았다. 고정 편집 영역 MAE는 최적화 목적과 관련된 진단값이며 독립적인 정확도 점수가 아니다.
