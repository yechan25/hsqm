# 여러 글자 공동 생성, 글자별 분석

[Colab에서 실행](https://colab.research.google.com/github/yechan25/hsqm/blob/main/notebooks/test_multiglyph_diffusion_scores.ipynb).

기존 한 글자 img2img 점검을 여러 글자 장면으로 확장한다. 학습 기준 이미지들을 한 장에
배치하고, 전체 장면에 잡음을 넣어 **한 번의 파이프라인 호출로 공동 역확산**한다.
글자별로 생성한 결과를 나중에 붙이는 방식이 아니다. 생성 후 처음 정한 칸 좌표로 잘라
기존 동결 Topo와 기존 source 점수를 적용한다. 새 학습이나 생성 중 guidance는 없다.

## 사용

1. 준비·Drive 연결. 기존 single-glyph와 동일한 모델/라이브러리.
2. 기존 학습 ZIP/TAR·CSV에서 필요한 manifest/NPZ를 자동 재생성한다.
3. 학습 기준 글자를 여러 개 선택한다. 기본은 9개. 문자명이 없으면 미리보기에서
   서로 다른 글자인지 확인한다. 모델은 숫자 파일명을 문자 코드로 바꾸지 않는다.
4. 기본 1/4/9개 글자 조건을 각각 전체 576x576에 놓고 strength .65/.85, seed100으로 생성한다.
   입력 대조군과 전체 생성 이미지를 그 셀에서 바로 표시하고 Drive에 보존한다.
5. 고정 칸별 원본 crop·기존 기준 획으로 추출/점수/추가 잉크 지도를 확인한다.

전체 이미지는 `page_*.png`, 잘라낸 이미지는 `sample_*_raw.png`, 실제 점수 입력은
`sample_*_scored.png`. JSON은 페이지 ID, 개수, 칸, bbox, 해당 학습 행을 기록한다.
`pilot_scores.csv`에도 이 대응을 남기며 진단 ZIP에는 전체 페이지와 crop을 모두 넣는다.
빈 칸·오자·옆 칸 이동·합쳐짐을 OCR나 분할 성공 기준으로 제외하지 않는다. 칸을 넘은
획은 고정 crop의 경계에 걸리므로 전체 페이지도 함께 확인해야 한다.

## 비교의 한계

- 각 조건은 선택 목록의 앞 N개를 사용한다. 개수별 평균의 문자 구성이 다르므로,
  동일 학습 행이 공통으로 포함된 경우를 짝지어 비교한다. 전체 한 글자 대조군이 필요하면
  나머지 기준도 별도로 single-glyph 시험을 수행한다.
- 전체 이미지 고정 모드에서는 글자 수와 글자당 해상도가 함께 변한다. 개수만의 인과
  효과로 해석하지 않는다. `FIXED_CELL_PIXELS=192`로 글자당 크기를 고정하는 추가 비교를
  할 수 있지만 이 경우 전체 이미지 크기·생성 비용·모델이 접하는 해상도가 달라진다.
- 다중 글자여도 img2img이므로 기준을 잘 유지할 수 있다. 실제 오류 증가를 보장하지 않는다.
  같은 시드가 서로 다른 이미지 크기에서 글자별로 동일한 잡음을 뜻하지는 않는다.
- 기존 원본 점수는 옅은 배경 누적에도 민감하다. 낮은 총점만으로 획 오류가 증가했다고
  판단하지 않는다. 원본과 누락/연결/정션/추가 잉크 위치, 문자 일치 여부를 함께 본다.
- 재구성 대조군은 실제 배치 이미지를 crop/resize한 것으로, 해상도 변환의 영향도 포함한다.

구현: `diffusion_model/multiglyph_pilot.py`. 노트북 재생성:
`python notebooks/build_multiglyph_diffusion_pilot.py`.

로컬 검사에서는 작은 합성 기준과 대체 생성기로 공동 호출 수, 원본 보존, 고정 crop의
좌표, 빈 글자 보존과 해상도 모드를 검증한다. 실제 사용자 GPU 생성 품질은 Colab 실행이
필요하며, 검증 전에는 오류가 늘거나 guidance로 개선됐다고 주장하지 않는다.

`python -m unittest discover -s tests -p test_multiglyph_pilot.py -v`
